## Where variables live

| File | Used by | Created from |
| --- | --- | --- |
| `backend/.env` | Laravel API | `backend/.env.example` |
| `frontend/.env` | Vite dev server and the Playwright runner | `frontend/.env.example` |
| `frontend/.env.local` | Optional personal overrides, loaded after `frontend/.env` by Playwright | created by hand |

`make install` and `make dev` create `backend/.env` from the example when it is missing, via `scripts/ensure-backend-env.sh` (the `backend-env` make target). The script generates an `APP_KEY` only when it is empty and never overwrites an existing key. `make install` also copies `frontend/.env.example` when `frontend/.env` is missing. The path is clone, `make install`, `make dev`, with no keys to obtain and no manual `.env` editing. None of the real files are committed (they are git-ignored); never put real secrets in the examples or in docs. Restart the servers after editing them. Vite only exposes variables that start with `VITE_`.

## Backend variables

Defined in `backend/.env.example`. Only the app-specific ones and the ones that matter for this project are listed; the rest are standard Laravel settings that can stay at their defaults.

| Variable | Purpose | Default | Required | Example |
| --- | --- | --- | --- | --- |
| `APP_KEY` | Laravel encryption key | empty in the example; generated automatically | yes | `base64:...` (generated by `make dev` / `make install`) |
| `APP_ENV` | Environment name | `local` | no | `local` |
| `APP_DEBUG` | Include stack traces in 500 responses | `true` | no | `false` in production |
| `APP_URL` | Base URL of the API | `http://localhost:8000` | no | `http://localhost:8000` |
| `CORS_ALLOWED_ORIGINS` | Comma-separated origins allowed by CORS for `api/*` | `http://localhost:5173` | no | `http://localhost:5173` |
| `JSON_STORAGE_PATH` | Directory for the JSON data files | `backend/storage/app/data` | no | `/var/data/review-queue` |
| `CACHE_STORE` | Cache driver | `file` | no | `file` |
| `SESSION_DRIVER` | Session driver (the API is stateless) | `array` | no | `array` |
| `QUEUE_CONNECTION` | Queue driver | `sync` | no | `sync` |
| `LOG_LEVEL` | Minimum log level | `debug` | no | `info` |

## Defaults when variables are missing

The backend boots with no `.env` file, or an empty one. Every setting the API uses has a safe default:

| Setting | Default |
| --- | --- |
| `APP_ENV` | `local` |
| `APP_DEBUG` | `false` |
| `CACHE_STORE` | `file` |
| `SESSION_DRIVER` | `file` (the API never uses sessions) |
| `QUEUE_CONNECTION` | `sync` |
| `CORS_ALLOWED_ORIGINS` | `http://localhost:5173` |
| `LOG_CHANNEL` | `stack` (single file) |
| `JSON_STORAGE_PATH` | `backend/storage/app/data` |

`APP_KEY` has no usable default. Without it every `/api` route except `/api/health` returns `503` (`app_not_configured`); `make dev` and `make install` generate it, so this only happens when you start the backend by hand. See [Troubleshooting](troubleshooting.md#503-from-the-api-not-configured).

## Health checks

`GET /api/health` always returns `200` and reports booleans only, so you can see what is missing without exposing values:

```json
{ "status": "ok", "checks": { "app_key": true, "storage_writable": true } }
```

`app_key` is true when `APP_KEY` is set, and `storage_writable` when the JSON storage directory (or the nearest existing parent) is writable.

## E2E-only variables

Read by the Playwright config (`frontend/playwright.config.ts`, `frontend/e2e/support/env.ts`). The suite needs no keys and no sign-in; both variables below are optional port overrides.

| Variable | Purpose | Default | Required | Example |
| --- | --- | --- | --- | --- |
| `E2E_FRONTEND_PORT` | Port of the E2E frontend server | `5199` | no | `5199` |
| `E2E_BACKEND_PORT` | Port of the E2E backend server | `8099` | no | `8099` |

The E2E backend server receives its own overrides: `JSON_STORAGE_PATH` (a temp directory), `CORS_ALLOWED_ORIGINS` (the E2E frontend origin), `CACHE_STORE=file` and a throwaway `APP_KEY` that protects no real data, so `make e2e` works with no `backend/.env` at all.

## No database

The backend does not use a database. `.env.example` sets `CACHE_STORE=file`, `SESSION_DRIVER=array` and `QUEUE_CONNECTION=sync` so nothing touches one, and `DB_CONNECTION` stays commented out. If your `.env` was created from an older template with `database` drivers, change those three values or the API may fail.
