## Where variables live

| File | Used by | Created from |
| --- | --- | --- |
| `backend/.env` | Laravel API | `backend/.env.example` |
| `frontend/.env` | Vite dev server and the Playwright runner | `frontend/.env.example` |
| `frontend/.env.local` | Optional personal overrides, loaded after `frontend/.env` by Playwright | created by hand |

`make install` copies the example files when the real ones do not exist. None of the real files are committed (they are git-ignored); never put real keys in the examples or in docs. Restart the servers after editing them. Vite only exposes variables that start with `VITE_`.

## Backend variables

Defined in `backend/.env.example`. Only the app-specific ones and the ones that matter for this project are listed; the rest are standard Laravel settings that can stay at their defaults.

| Variable | Purpose | Default | Required | Example |
| --- | --- | --- | --- | --- |
| `APP_KEY` | Laravel encryption key | empty | yes | generated by `php artisan key:generate` |
| `APP_ENV` | Environment name | `local` | no | `local` |
| `APP_DEBUG` | Include stack traces in 500 responses | `true` | no | `false` in production |
| `APP_URL` | Base URL of the API | `http://localhost:8000` | no | `http://localhost:8000` |
| `CLERK_SECRET_KEY` | Clerk secret key; also read by the E2E suite | empty | for E2E | `sk_test_xxx` |
| `CLERK_JWKS_URL` | Where to fetch Clerk's public keys | empty | yes | `https://your-instance.clerk.accounts.dev/.well-known/jwks.json` |
| `CLERK_ISSUER` | Expected `iss` claim; skipped when empty | empty | yes (recommended) | `https://your-instance.clerk.accounts.dev` |
| `CLERK_AUTHORIZED_PARTIES` | Comma-separated origins allowed in the `azp` claim; skipped when empty | `http://localhost:5173` | yes | `http://localhost:5173,http://localhost:5199` |
| `CORS_ALLOWED_ORIGINS` | Comma-separated origins allowed by CORS for `api/*` | `http://localhost:5173` | no | `http://localhost:5173` |
| `JSON_STORAGE_PATH` | Directory for the JSON data files | `backend/storage/app/data` | no | `/var/data/review-queue` |
| `CACHE_STORE` | Cache driver (holds the JWKS) | `file` | no | `file` |
| `SESSION_DRIVER` | Session driver (the API is stateless) | `array` | no | `array` |
| `QUEUE_CONNECTION` | Queue driver | `sync` | no | `sync` |
| `LOG_LEVEL` | Minimum log level | `debug` | no | `info` |

## Frontend variables

Defined in `frontend/.env.example`.

| Variable | Purpose | Default | Required | Example |
| --- | --- | --- | --- | --- |
| `VITE_CLERK_PUBLISHABLE_KEY` | Clerk publishable key. Without it the app shows a configuration error. | empty | yes | `pk_test_xxx` |
| `VITE_API_BASE_URL` | Base URL of the API, including `/api` | `http://localhost:8000/api` | no | `http://localhost:8000/api` |

## E2E-only variables

Read by the Playwright config and global setup (`frontend/playwright.config.ts`, `frontend/e2e/support/env.ts`). Playwright loads `frontend/.env`, then `frontend/.env.local`, and reads `CLERK_SECRET_KEY` from `backend/.env` when it is not already set.

| Variable | Purpose | Default | Required | Example |
| --- | --- | --- | --- | --- |
| `E2E_CLERK_USER_USERNAME` | Email of the Clerk test user the suite signs in as | none | for E2E | `test.user@example.com` |
| `CLERK_SECRET_KEY` | Creates the Clerk sign-in token (from the environment or `backend/.env`) | none | for E2E | `sk_test_xxx` |
| `E2E_FRONTEND_PORT` | Port of the E2E frontend server | `5199` | no | `5199` |
| `E2E_BACKEND_PORT` | Port of the E2E backend server | `8099` | no | `8099` |

The E2E backend server also receives overrides for `JSON_STORAGE_PATH` (a temp directory), `CORS_ALLOWED_ORIGINS` and `CLERK_AUTHORIZED_PARTIES` (set to the E2E frontend origin), and `CACHE_STORE=file`. If the Clerk variables are missing, the Clerk-dependent specs are skipped with a message.

## No database

The backend does not use a database. `.env.example` sets `CACHE_STORE=file`, `SESSION_DRIVER=array` and `QUEUE_CONNECTION=sync` so nothing touches one, and `DB_CONNECTION` stays commented out. If your `.env` was created from an older template with `database` drivers, change those three values or the API will answer `401` (see [Troubleshooting](troubleshooting.md)).
